# TimeWise Bot

`TimeWise` - Telegram-бот для автоматизации поздравлений и внутренних рассылок. Проект включает:

- ведение пользователей и ролей;
- ведение контактов и импорт `CSV` / `XLSX`;
- шаблоны сообщений;
- автоматическое создание событий по дням рождения;
- очередь согласования сообщений;
- Telegram-отправку через встроенный worker;
- отчеты, `/stats`, мониторинговые экраны.

## Что уже умеет бот

- Команды `/start`, `/help`, `/menu`, `/about`
- Роли `Admin`, `Editor`, `Viewer`
- Управление пользователями через бота
- Управление контактами: создание, просмотр, редактирование, удаление, фильтры, импорт
- Работа с шаблонами: просмотр, поиск по `id`, редактирование, версии
- Approval flow: просмотр карточек, правка текста, approve/reject, массовые действия за сегодня, правка сегодняшней пачки
- Отчеты по периодам `today` / `month` / `all` с выгрузкой `CSV` и `PDF`
- Команда `/stats` для администратора
- Автопланировщик событий по дням рождения
- Встроенный Telegram worker с retry-логикой

## Требования

- Python `3.11+`
- Telegram bot token от [@BotFather](https://t.me/BotFather)
- Для прод-режима рекомендуется PostgreSQL
- Для локального старта можно использовать SQLite

## Быстрый старт

### Windows PowerShell

```powershell
cd bot
python -m venv .venv
& ".venv\Scripts\python.exe" -m pip install -r requirements.txt
Copy-Item .env.example .env
```

После этого откройте `.env` и заполните как минимум:

- `BOT_TOKEN`
- `ADMIN_IDS`
- `DATABASE_URL`

Запуск:

```powershell
& ".venv\Scripts\python.exe" bot.py
```

### Универсально

```bash
python -m venv .venv
source .venv/bin/activate  # Linux/macOS
pip install -r requirements.txt
cp .env.example .env
python bot.py
```

## Настройка `.env`

Минимальный пример:

```env
BOT_TOKEN=1234567890:PUT_YOUR_TOKEN_HERE
ADMIN_IDS=111111111,222222222
DATABASE_URL=sqlite+aiosqlite:///timewise.db
DB_AUTO_CREATE=1
SCHEDULER_ENABLED=1
SCHEDULER_RUN_ON_STARTUP=1
SCHEDULER_DAILY_TIME=09:00
WORKER_ENABLED=1
WORKER_POLL_INTERVAL_SEC=5
RETRY_DELAYS_MIN=15,30,60
DEFAULT_MESSAGE_LANGUAGE=ru
```

### Основные переменные

- `BOT_TOKEN` - токен Telegram-бота
- `ADMIN_IDS` - список `tg_id` через запятую для стартового доступа администратора
- `DATABASE_URL` - строка подключения к БД
- `DB_AUTO_CREATE` - создавать таблицы автоматически при старте
- `SCHEDULER_ENABLED` - включить ежедневный планировщик
- `SCHEDULER_RUN_ON_STARTUP` - запускать цикл планировщика сразу при старте бота
- `SCHEDULER_DAILY_TIME` - ежедневное время запуска в формате `HH:MM`
- `WORKER_ENABLED` - включить встроенный worker
- `WORKER_POLL_INTERVAL_SEC` - интервал опроса очереди
- `RETRY_DELAYS_MIN` - задержки между повторами отправки в минутах
- `DEFAULT_MESSAGE_LANGUAGE` - язык сообщений по умолчанию

### SMTP-переменные

В конфиге поддерживаются:

- `SMTP_HOST`
- `SMTP_PORT`
- `SMTP_USER`
- `SMTP_PASSWORD`
- `SMTP_FROM_EMAIL`
- `SMTP_TLS`

Сейчас встроенный worker запускается для канала `Telegram`, поэтому для локального Telegram-тестирования `SMTP` не обязателен.

## База данных

По умолчанию проект может работать на `SQLite`:

- `DATABASE_URL=sqlite+aiosqlite:///timewise.db`

Для основной работы рекомендуется `PostgreSQL`, например:

```env
DATABASE_URL=postgresql+asyncpg://USER:PASSWORD@HOST:5432/DBNAME
```

Что важно знать:

- при `DB_AUTO_CREATE=1` таблицы создаются автоматически через `SQLAlchemy create_all`;
- для `PostgreSQL` при старте дополнительно выполняется проверка схемы;
- миграции `Alembic` пока не подключены, схема управляется текущими ORM-моделями.

## Что происходит при старте

Команда `python bot.py` запускает один процесс, внутри которого:

1. создается подключение к БД;
2. при необходимости создаются таблицы;
3. регистрируются роутеры и middleware;
4. запускается scheduler;
5. запускается встроенный worker для `Telegram`;
6. стартует polling Telegram-бота.

## Первая настройка после запуска

1. Добавьте в `.env` свой `tg_id` в `ADMIN_IDS`.
2. Запустите бота и отправьте `/start`.
3. Добавьте себя в таблицу пользователей через `/add_user`.
4. Убедитесь, что у вашей записи роль `Admin`.
5. После этого можно заводить контакты, шаблоны и тестировать рассылку.

## Команды

Общие:

- `/start` - приветствие и открытие панели по роли
- `/help` - список основных команд
- `/menu` - повторно открыть панель
- `/about` - краткая справка о проекте

Администратор:

- `/add_user` - добавить пользователя по `tg_id`
- `/users` - посмотреть список пользователей
- `/add_contact` - добавить контакт пошагово
- `/contacts` - посмотреть список контактов

- `/delete_contact` - удалить контакт
- `/import_contacts` - импортировать контакты из `CSV` / `XLSX`
- `/stats` - сводка по системе за сегодня

- `Мониторинг`
- `Отчёты`
- `Пользователи`
- `Настройки`
- `Approval`

Имеет полный доступ к управлению пользователями, контактами, шаблонами, согласованиями и отчетами.

### Editor

Видит разделы:

- `Контакты`
- `Шаблоны`
- `Approval`
- `Мониторинг`
- `Отчёты`
- `Помощь`

Может работать с контентом и контактами, но без админских операций по пользователям.

### Viewer

- `Шаблоны`
- `Помощь`

Роль только для просмотра.

## Руководство пользователя

### 1. Работа с пользователями

Только для `Admin`.

Основной сценарий:

1. Выполните `/add_user`.
2. Отправьте `tg_id` пользователя.
3. Выберите роль `Admin`, `Editor` или `Viewer`.
4. При необходимости откройте `/users` и проверьте результат.

### 2. Работа с контактами

Доступно для `Admin` и `Editor`.

Что можно делать:

- добавлять контакт вручную;
- открывать список контактов;
- фильтровать по компании, должности и ФИО;
- редактировать карточку;
- импортировать список контактов файлом.

Для ручного ввода:

- дата рождения: строго `YYYY-MM-DD`
- необязательное поле можно пропустить, отправив `-` или `пропустить`

### 3. Импорт контактов

Команда: `/import_contacts` или кнопка импорта в разделе `Контакты`.

Поддерживаемые форматы:

- `CSV`
- `XLSX`

Обязательные колонки:

```text
last_name, first_name, gender, birthday, tg_username, email, preferred_channel, default_style
```

Полный набор колонок:

```text
last_name, first_name, middle_name, gender, birthday, position, company, tz, tg_username, email, preferred_channel, default_style, segment, notes, is_active
```

Допустимые значения:

- `gender`: `Male`, `Female`, `М`, `Ж`
- `birthday`: `1999-12-31`
- `preferred_channel`: `Telegram` или `Email`
- `default_style`: `Friendly`, `Business`, `Official`

Результат импорта показывает:

- сколько строк обработано;
- сколько импортировано успешно;
- сколько ошибок валидации;
- сколько ошибок сохранения;
- список проблемных строк.

Готовые тестовые файлы лежат в корне проекта, например:

- `contacts_import_template.csv`
- `contacts_import_template.xlsx`
- `contacts_import_mixed_rows.csv`
- `contacts_import_mixed_rows.xlsx`

### 4. Шаблоны

Доступно для `Admin` и `Editor`, просмотр также доступен `Viewer`.

В разделе `Шаблоны` можно:

- смотреть список шаблонов;
- искать шаблон по `id`;
- открывать карточку шаблона;
- редактировать текст;
- включать и выключать шаблон;
- создавать новую версию.

### 5. Approval и согласование

Доступно для `Admin` и `Editor`, пакетные действия доступны `Admin`.

Основной сценарий:

1. Scheduler создает событие на дату дня рождения.
2. Для события создается текст сообщения.
3. Сообщение попадает в очередь согласования.
4. Ответственный пользователь открывает раздел `Approval`.
5. В карточке можно:
   - одобрить;
   - отклонить;
   - отредактировать текст.

Для `Admin` дополнительно доступны:

- `Одобрить всё за сегодня`
- `Отклонить всё за сегодня`
- `Править пачку за сегодня`

В режиме `Править пачку за сегодня` можно:

- открывать сегодняшние заявки по очереди;
- листать `предыдущая` / `следующая`;
- редактировать, approve или reject без возврата в общий список.

### 6. Отчеты и статистика

Доступно для `Admin`, `Editor`, `Viewer`.

Раздел `Отчёты` показывает:

- количество событий;
- количество одобренных, отклоненных и ожидающих согласования;
- успешность отправки;
- ошибки и ретраи;
- среднее время подготовки и доставки.

Доступны периоды:

- `today`
- `month`
- `all`

Можно скачать:

- `CSV`
- `PDF`

Команда `/stats` доступна только `Admin` и показывает краткую сводку за сегодня.

### 7. Мониторинг, события и сообщения

- `Мониторинг` нужен для технического просмотра очередей и состояний
- `Отчёты` нужны для аналитики и выгрузок
- `События` и `Сообщения` в роли `Viewer` работают в режиме чтения

## Типовой рабочий сценарий

1. Администратор добавляет пользователей.
2. Администратор или редактор добавляет контакты либо импортирует их файлом.
3. В базе уже должны быть шаблоны.
4. Scheduler находит контакты с днем рождения на текущую дату.
5. Для них создаются `events`, `messages`, `approval_queue`.
6. Ответственный открывает `Approval` и согласует тексты.
7. После approve создается или обновляется запись в `job_queue`.
8. Worker отправляет Telegram-сообщение и пишет результат в логи/статусы.
9. Пользователь открывает `Отчёты` или `/stats` для контроля результата.

## Структура проекта

- `bot.py` - точка входа
- `config.py` - чтение и валидация настроек
- `db/` - модели, сессии, репозитории, проверка схемы
- `handlers/` - команды и сценарии Telegram-бота
- `keyboards/` - inline-клавиатуры
- `middleware/` - логирование и проверка ролей
- `services/scheduler_service.py` - создание событий и заявок на согласование
- `services/worker_service.py` - фоновая отправка Telegram-сообщений
- `ui_helpers.py` - безопасное обновление сообщений и очистка временных ответов

## Частые проблемы

### Бот не стартует

Проверьте:

- заполнен ли `BOT_TOKEN`;
- доступна ли БД по `DATABASE_URL`;
- не сломан ли формат `SCHEDULER_DAILY_TIME`;
- установлены ли зависимости из `requirements.txt`.

### Ошибка подключения к PostgreSQL

Обычно это означает:

- неверный `DATABASE_URL`;
- база недоступна по сети;
- закрыт порт;
- неверный логин или пароль.

### При импорте контактов появляется `IntegrityError`

Обычно это значит, что строка дошла до БД, но нарушила ограничение:

- дубликат `tg_username` или `email`;
- недопустимое значение поля;
- конфликт с ограничением таблицы.

### Сообщения не отправляются

Проверьте:

- что событие одобрено;
- что в `job_queue` появилась задача;
- что у контакта корректный `tg_username`;
- что `WORKER_ENABLED=1`.
